# Migrating `model: string` → `llmConfig: LlmConfig` is a hard break

When we replaced the flat `model: string` field on `LlmNode` and `Agent` with the typed `llmConfig: LlmConfig` discriminated union (OAS-aligned), we deliberately chose not to ship a back-compat shim. Old call sites stop compiling. Old OAS JSON written by `toOAS` before this change does not deserialize cleanly through `fromOAS` — the resulting node has no `llmConfig` and the runner throws on first use.

The package is pre-1.0 and unpublished. There are no external consumers to protect. The JAMIA evaluation harness and any local cache directories are the only data-at-rest concerns, and both are cheap to regenerate. Carrying a back-compat path forever (factory overloads, runtime fallbacks, deserialization branches) would pay an ongoing complexity tax to solve a one-time migration problem.

## Considered options

- **None (chosen).** Break at the schema. Every caller migrates. Old JSON regenerated by re-running the topology.
- **OAS-only back-compat.** Detect old `model: string` in `fromOAS` and synthesize `createOpenAiConfig({ modelId })`. Rejected because (a) we don't have any persisted OAS JSON in this repo that needs to survive, and (b) future readers shouldn't have to remember which fields were ever `string` and are now nested.
- **Full back-compat at the factory boundary.** Accept `model: string` OR `llmConfig: LlmConfig` on `createLlmNode` / `createAgent`. Rejected as over-engineering for a pre-1.0 package.

Reopen this decision if the package is published and external consumers exist before another schema change happens.
