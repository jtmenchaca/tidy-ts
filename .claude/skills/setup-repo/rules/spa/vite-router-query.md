## `vite.config.ts`

**Plugin order matters.** `tanstackRouter` must come **before** `react`.

```ts
import { fileURLToPath, URL } from "node:url";
import tailwindcss from "@tailwindcss/vite";
import { tanstackRouter } from "@tanstack/router-plugin/vite";
import react from "@vitejs/plugin-react";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [
    tanstackRouter({
      target: "react",
      autoCodeSplitting: true,
      addExtensions: true,
    }),
    react(),
    tailwindcss(),
  ],
  resolve: {
    alias: {
      "@": fileURLToPath(new URL("./src", import.meta.url)),
    },
  },
  server: {
    host: true,
  },
  build: {
    outDir: "./dist/",
    emptyOutDir: true,
  },
});
```

## `src/main.tsx`

```tsx
/// <reference lib="dom" />
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { createRouter, RouterProvider } from "@tanstack/react-router";
import { StrictMode } from "react";
import ReactDOM from "react-dom/client";
import { routeTree } from "./routeTree.gen.ts";

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60 * 1000,
      gcTime: 30 * 60 * 1000,
      retry: false,
    },
  },
});

const router = createRouter({
  routeTree,
  context: { queryClient },
});

const rootElement = document.getElementById("root")!;
if (!rootElement.innerHTML) {
  const root = ReactDOM.createRoot(rootElement);
  root.render(
    <StrictMode>
      <QueryClientProvider client={queryClient}>
        <RouterProvider router={router} />
      </QueryClientProvider>
    </StrictMode>,
  );
}
```

## TanStack Router patch

Copy [assets/@tanstack__router-generator@1.139.7.patch](assets/@tanstack__router-generator@1.139.7.patch) into the repo's `patches/` directory:

```bash
mkdir -p patches
cp <skill-path>/rules/spa/assets/@tanstack__router-generator@1.139.7.patch patches/
```

The path the agent runs the skill from gives `<skill-path>` — usually `.claude/skills/setup-repo`.

Then wire it into the root `pnpm-workspace.yaml`:

```yaml
patchedDependencies:
  "@tanstack/router-generator": patches/@tanstack__router-generator@1.139.7.patch
```

**What the patch does:** loosens the Zod schema for `routeTreeFileFooter` in `@tanstack/router-generator` config — without it, certain function-shaped footers get rejected at validation. Pin to `1.139.7` in root `package.json` to keep the patch applying cleanly:

```json
"@tanstack/router-generator": "1.139.7"
```

If a future version of `@tanstack/router-generator` lands with this loosening upstream, drop the patch and bump the pin.

## Root `deno.jsonc` adjustments

Add the React/JSX block to the root `deno.jsonc` `compilerOptions` and exclude the generated route tree + build artifacts:

```jsonc
"compilerOptions": {
  "lib": ["deno.ns", "dom"],
  "jsx": "react-jsx",
  "jsxImportSource": "react",
  "jsxImportSourceTypes": "npm:@types/react@^19.0.8"
},
"exclude": ["**/node_modules/**", "dist/**", ".tanstack/**", ".vite/**", "**/routeTree.gen.ts"]
```

## Common Gotchas

- **Plugin order in `vite.config.ts`** — `tanstackRouter` must be first. If React's plugin runs before it, the generated route tree gets mis-processed.
- **`routeTree.gen.ts` is generated** — never edit by hand. Excluded from `tsconfig.app.json` and root `deno.jsonc`.
- **`@types/react` JSX source in root `deno.jsonc`** — without `jsxImportSourceTypes`, `deno check .` fails on JSX.
- **Strict TS settings catch unused vars** — `noUnusedLocals` + `noUnusedParameters` are on by design.
