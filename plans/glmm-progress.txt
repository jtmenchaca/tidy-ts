## Background

This implementation adds GLMM support to tidy-ts, targeting clinical/epidemiological use cases
where hierarchical data structures require random effects modeling (e.g., patients nested in
providers nested in clinics).

### Key Design Decisions

1. **Laplace Approximation** - Matches glmmTMB default, provides good balance of speed/accuracy
2. **Log-Cholesky Parameterization** - Unconstrained optimization for variance components
3. **Sparse Z Matrices** - Block-diagonal for nested, COO for crossed random effects
4. **Reuse GLM IRLS** - Existing infrastructure handles fixed effects estimation

### Reusable Components (from existing codebase)

- `glm_fit_core.rs` - IRLS algorithm (800+ lines)
- `qr_decomposition.rs` - Weighted least squares solver (420 lines)
- `family/*` - Gaussian, Binomial, Poisson, Gamma, InverseGaussian
- `gee/types.rs` - ClusterInfo structure
- `gee/correlation/*` - Exchangeable, AR1, Unstructured patterns

### New Components Required

1. **Random Effects Module** (`random_effects.rs`)
   - Z matrix construction (sparse)
   - Random effect likelihood
   - BLUP extraction

2. **Variance Components Module** (`variance_components.rs`)
   - Log-Cholesky parameterization
   - Theta <-> Sigma transformations
   - Jacobian for REML

3. **Laplace Module** (`laplace.rs`)
   - Joint log-likelihood
   - Mode finding (Newton)
   - Hessian computation
   - Marginal likelihood approximation

4. **Fitting Module** (`fitting.rs`)
   - Profile likelihood
   - Outer optimization (BFGS/Newton)
   - Convergence monitoring

5. **Families Extension**
   - Nbinom1, Nbinom2 families
   - Dispersion parameter handling

### Performance Targets

| Scenario | Target |
|----------|--------|
| 5000 obs, 50 groups, 1 RE | < 1 second |
| 10000 obs, 100 groups, 2 RE | < 5 seconds |
| Coefficient accuracy | Within 1e-4 of glmmTMB |
| SE accuracy | Within 1e-3 of glmmTMB |

**Key Functions Implemented:**

   - `theta_to_corr()` - Compute correlation matrix from theta
   - `vcov_to_corr()` - Convert covariance to correlation matrix

3. **Jacobian for REML:**
   - `theta_to_vcov_jacobian()` - Numerical Jacobian of theta → vcov transformation
   - `log_jacobian_determinant()` - Analytical log|J| for likelihood adjustment
   - `log_jacobian_determinant_gradient()` - Gradient of log|J| w.r.t. theta

4. **Initialization Helpers:**
   - `initial_theta()` - Create starting theta for different covariance structures
   - `theta_to_variance_component()` - Convert theta to VarianceComponent struct
   - `total_theta_params()` - Count total parameters across random effects
   - `split_theta()` - Split combined theta vector into per-effect slices

**Parameterization Details:**

For a k×k covariance matrix:
- First k parameters: `theta[0..k] = log(diag(L))` (ensures positive diagonal)
- Remaining k(k-1)/2 parameters: `theta[k..] = L[i,j]` for i > j (off-diagonal, unconstrained)

This gives k(k+1)/2 parameters total, matching lme4/glmmTMB convention.

**Supported Covariance Structures:**
- `Independent`: k params (diagonal only, no correlation)
- `Unstructured`: k(k+1)/2 params (full log-Cholesky)
- `CompoundSymmetry`: 2 params (shared variance, shared correlation via tanh transform)

### 2026-02-02: Item 6 Complete - Random Effects Log-Likelihood

Implemented the random_effects_likelihood module for computing log p(b | theta) and its gradients.

**Files Created:**

**Files Modified:**
- `packages/dataframe/rust/stats/regression/glmm/mod.rs` - Added module export and re-exports

**Key Functions Implemented:**

1. **Core Likelihood Computation:**
   - `log_random_effects_prior(b, theta, random_effects)` → `RandomEffectsPrior`
     - Computes log p(b | theta) for all random effects across all groups
     - Returns log-likelihood, gradient w.r.t. b, and gradient w.r.t. theta
   - `log_random_effects_prior_value(b, theta, random_effects)` → `f64`
     - Faster version returning only the log-likelihood (no gradients)

2. **Single Group Computation:**
   - `log_prior_one_group(b_group, theta_re, k, cov_type)` → (log_lik, grad_b, grad_theta)
     - Core computation for one group's contribution to the prior
     - Uses Cholesky decomposition for numerical stability

3. **Supporting Functions:**
   - `compute_vcov_for_type(theta_re, k, cov_type)` → covariance matrix
     - Supports Independent, Unstructured, and CompoundSymmetry
   - `forward_solve(L, b)` - Solves L*y = b via forward substitution
   - `backward_solve(L, y)` - Solves L^T*x = y via back substitution
   - `compute_precision_matrix(theta_re, k, cov_type)` → Σ^{-1}
   - `compute_block_precision_matrices(theta, random_effects)` → list of precision matrices

4. **Gradient Computation:**
   - Analytical gradient d/db: `-Σ^{-1} * b`
   - Numerical gradient d/dtheta: Central differences with ε=1e-7

**Mathematical Formula:**
```
log p(b | θ) = -0.5 * b' Σ^{-1} b - 0.5 log|Σ| - (q/2) log(2π)

where:
- b is the random effects vector
- Σ is the covariance matrix derived from θ
- q is the dimension of b
```

**Data Structures:**

```rust
pub struct RandomEffectsPrior {
    pub log_likelihood: f64,    // log p(b | theta)
    pub grad_b: Vec<f64>,       // d/db
    pub grad_theta: Vec<f64>,   // d/dtheta
}
```

**Block Structure:**
- Σ is block-diagonal with one block per group within each random effect
- Each group's contribution computed independently (efficient for large n_groups)
- Memory scales linearly with n_groups, not quadratically

### 2026-02-02: Item 7 Complete - Laplace Approximation for Marginal Likelihood

Implemented the laplace module for computing the Laplace approximation to the marginal likelihood of GLMMs.

**Files Created:**
- `packages/dataframe/rust/stats/regression/glmm/laplace.rs` (~500 lines)

**Files Modified:**
- `packages/dataframe/rust/stats/regression/glmm/mod.rs` - Added `pub mod laplace;` and re-exports

**Key Functions Implemented:**

1. **Core Likelihood Computation:**
   - `joint_log_likelihood(y, x, z, beta, b, theta, random_effects, family, weights, offset)` → `f64`
     - Computes: log p(y | b, β, θ) + log p(b | θ)
     - Data likelihood via GLM deviance function
     - Prior from random_effects_likelihood module

2. **Gradient Computation:**
   - `joint_gradient_b(...)` → `Vec<f64>`
     - Gradient w.r.t. random effects b
     - Data contribution: Z^T * working_residuals
     - Prior contribution: -Σ^{-1} * b
     - Uses family's variance and mu_eta functions

3. **Hessian Computation:**
   - `joint_hessian_b(...)` → `Vec<Vec<f64>>`
     - Hessian of negative joint log-likelihood
     - Data part: Z^T * diag(IRLS_weights) * Z via `weighted_cross_product()`
     - Prior part: block-diagonal precision matrices via `compute_block_precision_matrices()`

4. **Mode Finding (Inner Optimization):**
   - `find_b_mode(y, x, z, beta, b_init, theta, random_effects, family, weights, offset, control)` → (b_mode, iterations, converged)
     - Newton's method with Cholesky solver
     - Damping factor for stability
     - Regularization for ill-conditioned Hessians
     - Gradient descent fallback if Cholesky fails

5. **Laplace Approximation:**
   - `laplace_approximation(...)` → `LaplaceResult`
     - Full result including: marginal likelihood, mode, gradient w.r.t. theta, Hessian
   - `laplace_marginal_likelihood(...)` → `f64`
     - Convenience function returning only the value (faster)

6. **Supporting Functions:**
   - `solve_linear_system(A, b)` → solve A*x = b via Cholesky
   - `log_determinant(A)` → log|A| via Cholesky
   - `numerical_grad_theta(...)` → gradient of marginal likelihood w.r.t. theta

**Data Structures:**

```rust
pub struct LaplaceResult {
    pub log_marginal_likelihood: f64,  // Laplace-approximated marginal
    pub b_mode: Vec<f64>,              // Mode of random effects (BLUPs)
    pub grad_theta: Vec<f64>,          // Gradient for outer optimization
    pub hessian_b: Option<Vec<Vec<f64>>>,  // Hessian at mode (for SEs)
    pub inner_iterations: usize,
    pub inner_converged: bool,
}

pub struct LaplaceControl {
    pub max_iter: usize,      // Default: 100
    pub tol: f64,             // Default: 1e-8
    pub damping: f64,         // Default: 1.0
    pub compute_hessian: bool, // Default: true
    pub min_variance: f64,     // Default: 1e-10 (regularization)
}
```

**Algorithm Overview:**

```
log p(y | β, θ) ≈ log p(y, b̂ | β, θ) - 0.5 * log|H|

where:
- b̂ = argmax_b [log p(y | b, β, θ) + log p(b | θ)]  (found by Newton)
- H = Hessian of negative joint log-likelihood at b̂
- H = Z^T W Z + Σ^{-1}  (block-diagonal structure)
```

**Algorithm Overview:**

```
glmm_fit(y, x, z, random_effects, family, control):
  1. Initialize theta (variance components) from random_effects
  2. Initialize beta (fixed effects) to zeros or user-supplied values
  3. Initialize b (random effects) to zeros

  for outer_iter = 1 to max_iter_outer:
    4. Evaluate Laplace-approximated marginal likelihood at current theta
       - Inner loop finds b_mode via Newton's method
       - Returns log_marginal_likelihood and grad_theta

    5. Compute L-BFGS search direction from gradient and history

    6. Line search to find optimal step size

    7. Update theta using step and direction

    8. Update L-BFGS history (s, y pairs)

    9. Check convergence via gradient norm < tol_outer

  10. Extract final results: theta, beta, b, variance_components, BLUPs

  return GlmmResult
```

**Key Design Decisions:**

1. **L-BFGS over BFGS** - Limited memory for larger problems, O(mn) vs O(n²)
2. **Backtracking line search** - Simple and robust, Armijo condition only
3. **Best solution tracking** - Keeps track of best theta in case of non-monotonic behavior
4. **Gradient descent fallback** - When L-BFGS direction fails
5. **Builds on Laplace module** - Uses existing `laplace_approximation()` for objective/gradient

### 2026-02-02: Item 9 Complete - BLUP Extraction and Standard Errors

Fixed the BLUP standard error computation to use the correct formula: SE = sqrt(H^{-1}[i,i]) instead of the incorrect sqrt(1/H[i,i]).

**Files Modified:**
- `packages/dataframe/rust/stats/regression/glmm/laplace.rs` - Added `invert_symmetric_positive_definite()` function
- `packages/dataframe/rust/stats/regression/glmm/mod.rs` - Added export for new function
- `packages/dataframe/rust/stats/regression/glmm/fitting.rs` - Rewrote `build_blups()` with correct SE computation

**Key Changes:**

1. **Matrix Inversion Function** (`laplace.rs:371-421`):
   - `invert_symmetric_positive_definite(a)` → `Option<Vec<Vec<f64>>>`
   - Uses Cholesky decomposition: A = LL^T
   - Computes L^{-1} via forward substitution
   - Returns A^{-1} = L^{-T} L^{-1}
   - Used to compute conditional variance Var(b|y) = H^{-1}

2. **Corrected BLUP Standard Errors** (`fitting.rs:613-696`):
   - **Before (incorrect)**: `SE = sqrt(1/H[i,i])` - inverts diagonal elements only
   - **After (correct)**: `SE = sqrt(H^{-1}[i,i])` - extracts diagonal of full inverse
   - These are only equal when H is diagonal; for non-diagonal H they differ significantly

3. **Conditional Variance-Covariance Extraction**:
   - Now extracts full k×k blocks for each group from H^{-1}
   - Stored in `RandomEffectEstimates.conditional_vcov`
   - Previously was always `None`

**Mathematical Background:**

For GLMMs, the conditional distribution of random effects given data is:
```
b | y ~ N(b_hat, H^{-1})
```
where:
- b_hat is the mode (conditional on fixed effects and variance components)
- H is the Hessian of the negative joint log-likelihood at b_hat
- H = Z^T W Z + Σ^{-1}

The **conditional standard error** of b_i is:
```
SE(b_i | y) = sqrt(Var(b_i | y)) = sqrt(H^{-1}[i,i])
```

The old code computed `sqrt(1/H[i,i])`, which is fundamentally different:
- `1/H[i,i]` ignores correlations between random effects
- `H^{-1}[i,i]` accounts for the full covariance structure

In `laplace.rs`:
- `test_invert_symmetric_positive_definite_identity` - Identity inverts to itself
- `test_invert_symmetric_positive_definite_diagonal` - Diagonal matrix inversion

### 2026-02-02: Item 11 Complete - GLMM with Poisson Family

Extended the GLMM implementation to support Poisson family with log link, fixing several bugs in the process.

**Files Modified:**
- `packages/dataframe/rust/stats/regression/glmm/fitting.rs` - Added Poisson tests, fixed beta initialization
- `packages/dataframe/rust/stats/regression/glmm/laplace.rs` - Fixed infinite recursion bug

**Key Bug Fixes:**

1. **Infinite Recursion (previously fixed):**
   - `laplace_approximation()` → `numerical_grad_theta()` → `laplace_approximation()` caused stack overflow
   - Fixed by adding `compute_gradient: bool` flag to `LaplaceControl`

2. **Fixed Effects Initialization:**
   - Beta was always initialized to zeros, which doesn't work well for non-Gaussian families
   - For Poisson with log link, a zero intercept means exp(0) = 1 baseline count
   - **Fix:** Initialize intercept to `link(mean(y))`:
     ```rust
     let y_mean = y.iter().sum::<f64>() / n as f64;
     let init_mu = vec![y_mean.max(0.01)];
     let init_eta = family.link().linkfun(&init_mu);
     init_beta[0] = init_eta[0];
     ```
   - This ensures the initial linear predictor produces sensible fitted values

- `cargo test test_glmm` passes (12/12 tests)
- `pnpm check` passes (all green)

**Technical Notes:**

For Poisson GLMMs:
- Data likelihood: log p(y|μ) = y*log(μ) - μ - log(y!)
- Link function: η = log(μ) → μ = exp(η)
- Variance function: V(μ) = μ
- IRLS weights: w = μ (derivative of link × inverse variance)

The key insight for non-Gaussian families is that proper initialization
of beta is crucial. With log link, beta₀ = 0 means baseline μ = 1,
which may be far from the data mean. Starting from log(mean(y)) gives
a much better initial point for optimization.
